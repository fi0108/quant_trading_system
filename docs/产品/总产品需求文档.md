## 一、项目定位与目标

### 1.1 项目定位
个人小型**生产级**量化交易平台，用于A股/美股/港股市场的策略自动化交易。

**关键特征**：
- **个人项目**：一人或小团队，一人多角色
- **小型规模**：管理资金规模适中，策略数量有限（2-5个）
- **生产级要求**：真实资金运作，必须保证稳定性、安全性、可追溯性

### 1.2 核心目标
1. **自动化交易**：策略信号自动生成、风控检查、下单执行
2. **风险可控**：多层风控机制，防止异常损失
3. **稳定运行**：7×24小时稳定运行（交易时段），断线自动恢复
4. **可追溯**：所有操作有日志，可回溯分析

### 1.3 非目标（不做）
- ❌ 多账户管理（只支持单账户）
- ❌ 分布式架构（单机部署）
- ❌ 机器学习平台（策略为规则型，不涉及模型训练）
- ❌ 复杂Web界面（命令行为主，简单可视化即可）

## 四、全局边界与约束

### 4.1 数据处理边界
- **行情存储**：只存储策略需要的标的分钟级数据，不存Tick级
- **缓存策略**：Redis保留最近100根K线
- **数据源优先级**：本地数据库 > 外部API（减少API调用）

### 4.2 交易执行边界
- **并发限制**：同一标的同时只能有1个活跃订单
- **订单幂等性**：相同信号60秒内只下单1次（防止重复）
- **超时设置**：API调用10秒超时，数据库查询5秒超时

### 4.3 风控边界
- **单票持仓限制**：不超过总资金30%
- **总仓位限制**：不超过总资金80%（保留20%现金）
- **单日交易次数**：最多20次（防止过度交易）
- **当日亏损限制**：达到总资金2%停止新开仓

### 4.4 系统运行边界
- **运行环境**：单机部署（Windows/Linux）
- **数据库规模**：预估1年数据量 < 10GB
- **内存占用**：稳态运行 < 1GB
- **CPU占用**：平均 < 30%

## 六、关键决策点

### 6.1 持仓数据源
**决策**：以IBKR账户为权威源，本地维护副本
- **同步策略**：每5分钟对账一次
- **差异处理**：差异>1股则告警，人工确认

### 6.2 风控检查时机
**决策**：前置检查为主，持续监控为辅
- **前置检查**（订单提交前）：资金/持仓/频率 ← 必须
- **持续监控**（运行时）：止损止盈 ← 必须
- **后置检查**（成交后）：异常成交检测 ← V2再加

### 6.3 策略触发机制
**决策**：定时触发为主
- **触发频率**：每分钟检查一次
- **触发条件**：时间到达 + 数据已更新
- **事件驱动**：V2支持（价格突破、新闻事件）

### 6.4 订单未成交处理
**决策**：限价单超时撤单，市价单直接成交
- **限价单**：30秒未成交 → 撤单 → 价格追踪重发（最多3次）
- **市价单**：直接提交，接受滑点
- **订单拒绝**：记录原因，不自动重试

## 七、风险点与验证标准

### 7.1 高风险点（必须测试）

#### 风险1：重复下单
**场景**：网络重试导致同一信号下单2次  
**防护**：订单幂等性（唯一ID + 60秒内去重）  
**验证**：模拟网络抖动，确认不会重复下单

#### 风险2：状态不同步
**场景**：本地持仓与IBKR账户不一致  
**防护**：定期对账 + 差异告警  
**验证**：手动从IBKR调整持仓，确认系统发现并告警

#### 风险3：风控失效
**场景**：风控检查被绕过或计算错误  
**防护**：单元测试覆盖所有风控规则  
**验证**：构造超限场景，确认被拒绝

#### 风险4：断线未恢复
**场景**：系统以为在运行但实际未连接  
**防护**：心跳检测 + 连接状态监控  
**验证**：断开连接，确认1分钟内告警

### 7.2 阶段验收标准

| 阶段 | 验收标准 | 验证方法 |
|------|---------|---------|
| 阶段一 | 稳定运行24小时不断线，数据完整 | 模拟盘长稳测试 |
| 阶段二 | 手动下单100次，订单状态100%准确 | 模拟盘压力测试 |
| 阶段三 | 策略运行1周，无逻辑错误 | 模拟盘策略测试 |
| 阶段四 | 模拟断线/异常，自动恢复 | 异常注入测试 |
| 上线前 | 真实环境只读验证通过 | 生产只读验证 |
