## 2026-08-25: 统一IBKR客户端

### 变更类型
🔧 **重构 (Refactoring)**

### 变更原因
在阶段一开发过程中，发现存在两个功能重叠的IBKR客户端：
- `ConnectionManager` (src/trading/connection/manager.py) - 只有连接管理
- `IBKRClient` (src/data/ibkr_client.py) - 功能完整（连接+数据+订单）

**问题**：
- Demo脚本使用了功能不完整的 `ConnectionManager`
- 导致 `subscribe_market_data` 方法不存在错误
- 项目中90%的地方使用 `IBKRClient`，只有10%使用 `ConnectionManager`

### 变更内容

#### 1. 统一使用 IBKRClient
```python
# ❌ 旧代码（已废弃）
from trading.connection.manager import ConnectionManager
manager = ConnectionManager(host='127.0.0.1', port=7497, client_id=1)
manager.connect()
manager.subscribe_market_data('AAPL')  # ❌ 方法不存在

# ✅ 新代码（推荐）
from data.ibkr_client import IBKRClient
client = IBKRClient(host='127.0.0.1', port=7497, client_id=1)
client.connect()
client.subscribe_realtime_bars('AAPL', callback=on_bar)  # ✅ 正确方法
```

#### 2. 修改的文件
- `scripts/demo/run_integrated_demo.py` - 改用 IBKRClient
- `scripts/demo/quick_test.py` - 改用 IBKRClient

#### 3. 保留的旧代码
- `src/scheduling/scheduler.py` - 仍使用 ConnectionManager
  - **原因**: 暂时保留，计划后续迁移
  - **计划**: Week5 迁移到 IBKRClient

### 影响范围

**直接影响**:
- Demo脚本现在可以正常订阅数据
- 所有使用 ConnectionManager 的代码需要评估是否迁移

**间接影响**:
- 架构更清晰：一个统一的IBKR客户端
- 减少维护成本：不需要维护两套类似代码

### 迁移指南

#### 连接管理
```python
# 旧
manager = ConnectionManager(...)
manager.connect()
if manager.is_connected():
    pass

# 新
client = IBKRClient(...)
client.connect()
if client.is_connected():
    pass
```

#### 数据订阅
```python
# 旧（不存在的方法）
req_id = manager.subscribe_market_data(symbol)

# 新
def on_bar(bars, has_new_bar):
    if has_new_bar:
        bar = bars[-1]
        # 处理数据

client.subscribe_realtime_bars(symbol, callback=on_bar)
```

#### 断开连接
```python
# 旧
manager.disconnect()

# 新
client.disconnect()
```

### 遗留问题

1. **scheduler.py 未迁移**
   - 位置: `src/scheduling/scheduler.py`
   - 状态: 仍使用 ConnectionManager
   - 计划: Week5 评估并迁移

2. **ConnectionManager 是否完全废弃**
   - 当前: 保留但不推荐
   - 长期: 考虑完全移除或重构为 IBKRClient 的一部分

### 决策记录

**为什么选择 IBKRClient 而不是 ConnectionManager？**
1. ✅ 功能更完整（连接+数据+订单）
2. ✅ 使用更广泛（90% vs 10%）
3. ✅ 接口更统一（一个类搞定所有IBKR操作）
4. ✅ 维护成本更低（只维护一套代码）

## 2026-08-25: 统一导入路径规范

### 变更类型
🔧 **规范化 (Standardization)**

### 变更原因
阶段一开发过程中，导入路径混乱：
- 有些文件用 `from src.common.xxx`
- 有些文件用 `from common.xxx`
- 测试、脚本、源码导入规范不一致

**问题**：
- 花费6小时修复导入错误
- 代码维护困难
- 新人容易犯错

### 变更内容

#### 1. 统一规范：全部使用相对路径

```python
# ✅ 正确 - 统一使用相对路径
from common.config import Config
from data.ibkr_client import IBKRClient
from risk.manager import RiskManager

# ❌ 错误 - 禁止使用 src. 前缀
from src.common.config import Config
from src.data.ibkr_client import IBKRClient
```

#### 2. 前提条件：安装为可编辑包

```bash
# 必须执行（一次性）
pip install -e .
```

**原理**：
- 将 `src/` 目录添加到 Python 路径
- 所有文件（包括scripts）都能直接导入
- 无需手动添加 `sys.path`

#### 3. 修改的文件（24个）

**src/ 目录**：14个文件
- data/validator.py
- database/safe_connection.py
- monitor/alert_manager.py
- monitor/alert_deduplicator.py
- monitor/strategy_monitor.py
- monitor/system_monitor.py
- risk/manager.py
- risk/rules/order_rules.py
- risk/rules/position_rules.py
- trading/connection/monitor.py
- 等...

**tests/ 目录**：6个文件
- tests/slice4/unit/*.py
- tests/slice3/unit/*.py
- tests/slice3/integration/*.py

**scripts/ 目录**：3个文件
- scripts/demo/quick_test.py
- scripts/demo/run_integrated_demo.py
- scripts/run_strategy.py

**strategies/ 目录**：1个文件
- strategies/sma_crossover_live.py

### 影响范围

**积极影响**:
- ✅ 导入路径统一，易于维护
- ✅ 符合Python最佳实践
- ✅ 新增代码不会犯错
- ✅ 所有测试通过（66个测试）

**注意事项**:
- ⚠️ 新环境需要执行 `pip install -e .`
- ⚠️ 虚拟环境切换后需要重新安装
