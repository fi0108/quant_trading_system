## 一、开发原则

### 核心理念

1. **架构先行**：前期投入时间做好设计，避免后期推倒重来
2. **模块独立**：每个模块接口明确，内部实现可迭代
3. **测试同步**：开发过程中同步编写测试
4. **文档同步**：代码和文档同步更新

### 避免重构的关键

- ✅ 数据库表结构一次设计到位
- ✅ 核心接口一次定义清楚
- ✅ 配置化而非硬编码
- ✅ 分层清晰，依赖解耦

## 三、阶段 1：实盘交易能力（4 周，100-120h）

**目标**：能在 IBKR 模拟盘稳定运行简单策略

### Week 1：Hello World 版本（25-30 小时）

**交付标准**：在纸盘下出第一个订单并成交

**任务分解**：

1. **IBKR 连接和实时数据订阅（8小时）**

   - 连接 IBKR Gateway
   - 订阅单个标的（AAPL）5秒 Bar
   - 数据推送到策略
2. **固定买入策略（2小时）**

   - 每收到 10 次数据买入 1 股
   - 不看价格、不看持仓
3. **订单管理（5小时）**

   - 接收信号创建市价单
   - 提交到 IBKR
   - 打印订单 ID
4. **基础风控（3小时）**

   - 检查账户现金 > $200
   - 不足则拒绝下单
5. **持仓查询（3小时）**

   - 从 IBKR 查询当前持仓
   - 打印持仓列表
6. **日志记录（2小时）**

   - Loguru 记录关键事件
7. **集成测试（2小时）**

   - 端到端运行验证

**不做**：❌ 回测 ❌ 数据库 ❌ 复杂策略 ❌ 监控告警

---

### Week 2：基础设施完善（25-30 小时）

**交付标准**：持续运行 3 天不崩溃

**任务分解**：

1. **订单状态跟踪（6小时）**

   - 监听订单状态变化
   - 成交后更新持仓
   - 记录订单历史
2. **持仓管理（6小时）**

   - 本地持仓跟踪
   - 与 IBKR 定期同步（每分钟）
   - 盈亏计算
3. **断线重连（6小时）**

   - 检测连接断开
   - 自动重连（指数退避）
   - 重连后重新订阅
4. **PostgreSQL 存储（6小时）**

   - 订单表、持仓表
   - 基础 ORM 封装
   - 数据持久化
5. **基础监控（4小时）**

   - 系统状态检查（连接、内存、CPU）
   - 邮件告警（连接断开、订单拒绝）

**不做**：❌ Redis ❌ 复杂告警 ❌ 性能优化

---

### Week 3：策略框架（25-30 小时）

**交付标准**：能运行 SMA 双均线策略

**任务分解**：

1. **QCAlgorithm 基类（8小时）**

   - Initialize / OnData / OnOrderEvent 生命周期
   - AddEquity、MarketOrder、LimitOrder API
   - Portfolio、Account 属性
2. **技术指标库（6小时）**

   - SMA、EMA
   - 自动预热机制
3. **历史数据下载（6小时）**

   - 从 IBKR 下载日线数据
   - 存储到 PostgreSQL
   - 断点续传
4. **策略示例（4小时）**

   - SMA 双均线策略
   - 在实盘运行验证

**不做**：❌ 复杂指标（MACD、RSI 等后续加） ❌ 多标的同时运行

---

### Week 4：稳定性强化（25-30 小时）

**交付标准**：模拟盘运行 1 周无人工干预

**任务分解**：

1. **异常处理完善（6小时）**

   - 所有关键路径异常捕获
   - 降级处理（数据缺失、网络超时）
2. **风控增强（6小时）**

   - 单只股票持仓上限
   - 单日交易次数限制
   - 单笔订单金额上限
3. **监控优化（6小时）**

   - 告警去重（5分钟内相同告警合并）
   - 系统资源监控
   - 策略状态监控
4. **数据质量检查（4小时）**

   - 行情数据异常检测
   - 缺失数据处理
5. **文档（4小时）**

   - 部署文档
   - 使用文档

**验收标准**：

- ✅ 模拟盘连续运行 7 天
- ✅ 无系统崩溃
- ✅ 订单执行准确
- ✅ 持仓与 IBKR 一致
- ✅ 关键异常有告警

## 四、阶段 2：回测引擎（3 周，75-90h）

**目标**：能用历史数据验证策略

### Week 5：回测引擎核心（25-30 小时）

**任务分解**：

1. **回测引擎框架（10小时）**

   - 时间循环
   - 数据分发到策略
   - 订单模拟成交
   - 权益曲线记录
2. **成交模拟（6小时）**

   - 市价单：下一根 Bar 开盘价成交
   - 限价单：价格触达时成交
   - 手续费计算（IBKR 费率）
3. **统一策略接口（6小时）**

   - 策略在回测和实盘使用相同代码
   - 通过 Mode 参数区分
4. **回测数据加载（4小时）**

   - 从 PostgreSQL 加载历史数据
   - 按时间排序推送

---

### Week 6：绩效分析（25-30 小时）

1. **绩效指标计算（10小时）**

2. **可视化输出（8小时）**

   - 交易明细表
3. **回测报告（4小时）**

   - 生成 HTML 报告
   - 包含所有指标和图表

## 九、风险管理

### 进度风险应对

**如果某周延期**：

1. 评估影响范围
2. 调整后续计划
3. 降低功能完成度（保留核心功能）
4. 不要试图"赶工"，稳扎稳打

**如果遇到技术难题**：

1. 时间盒限制（最多 4 小时）
2. 寻求社区帮助
3. 考虑替代方案
4. 必要时调整架构

### 质量保证

**每周检查**：

- 单元测试覆盖率 > 80%
- 关键路径集成测试通过
- 代码审查（自我审查）
- 文档同步更新
