## 一、什么是垂直切片？

### 定义
垂直切片是一个**端到端**的功能单元，从用户界面（或 CLI）到数据库，跨越所有架构层，能独立交付业务价值。

### 水平开发 vs 垂直开发

❌ **水平开发**（模块式）：
```
Week 1: 完成数据层 100%
Week 2: 完成策略层 100%
Week 3: 完成引擎层 100%
→ 结果：3周后才能跑通第一个完整流程
```

✅ **垂直开发**（切片式）：
```
Week 1: 切片1 - 数据接入验证（数据层30% + CLI验证）
Week 2: 切片2 - 简单策略执行（策略层30% + 引擎层30%）
Week 3: 切片3 - 订单执行验证（券商层30% + 完整流程）
→ 结果：每周都能跑通一个完整场景
```

### 切片的好处
1. **快速验证**：及时发现架构问题
2. **持续交付**：每周都有可演示成果
3. **风险控制**：问题早暴露
4. **保持动力**：看到进展不容易放弃

## 二、切片设计原则

### 原则 1：端到端价值
每个切片必须：
- 有明确的输入和输出
- 能独立运行和验证
- 交付可见的业务价值

### 原则 2：最小化依赖
- 尽量减少外部依赖
- 可以用 Mock 或简化实现
- 先跑通主流程，后完善细节

### 原则 3：风险优先
优先实现高风险部分：
- 技术不确定性高的
- 业务核心路径
- 容易出错的环节

### 原则 4：可增量
- 后续切片复用前面的代码
- 每个切片只增加新功能
- 不推倒重来

## 四、每个切片的详细设计

### 切片1：数据接入验证（Week 1）

**业务场景**：作为开发者，我想验证能否从 IBKR 获取实时行情

**验收标准**：
- 运行脚本后，终端每5秒打印一次 AAPL 的最新价格
- 连续运行1小时不断线
- 断开网络后能自动重连

**技术路径**：
```
1. IBKR 连接
   ↓
2. 订阅 AAPL 5秒Bar
   ↓
3. 收到数据回调
   ↓
4. 打印到终端（不存数据库）
   ↓
5. 断线重连机制
```

**需要实现的最小模块**：
- `src/broker/ibkr_client.py`：IBKR 连接管理
- `src/data/realtime_feed.py`：实时数据订阅
- `scripts/test_data_feed.py`：验证脚本

**Mock/简化部分**：
- ❌ 不需要数据库
- ❌ 不需要多标的订阅
- ❌ 不需要数据清洗

**输出物**：
```bash
$ python scripts/test_data_feed.py

[INFO] 2026-08-17 09:30:05 - Connecting to IBKR...
[INFO] 2026-08-17 09:30:06 - Connected successfully
[INFO] 2026-08-17 09:30:07 - Subscribing AAPL 5-sec bars
[DATA] 2026-08-17 09:30:10 - AAPL: O=150.20 H=150.25 L=150.18 C=150.22 V=5000
[DATA] 2026-08-17 09:30:15 - AAPL: O=150.22 H=150.30 L=150.20 C=150.28 V=6200
...
```

**技术路径**：
```
1. 设计数据库表结构
   ↓
2. 实现数据库操作层
   ↓
3. 数据接收后保存到数据库
   ↓
4. 实现订单管理（本地记录）
   ↓
5. 实现持仓跟踪
   ↓
6. 日志系统配置
```

**需要实现的模块**：

- `src/broker/position_tracker.py`：持仓跟踪
- `src/common/logger.py`：日志配置
- `scripts/init_db.py`：数据库初始化

**复用切片1**：
- ✅ IBKR 连接
- ✅ 实时数据订阅

**输出物**：
- 数据库中有历史行情数据
- 能查询订单和持仓记录
- 日志文件记录完整

### 切片3：策略框架验证（Week 3）

**业务场景**：作为策略开发者，我想用统一的 API 编写策略

**验收标准**：
- 编写一个 SMA 双均线策略
- 策略能接收实时数据
- 策略能生成买卖信号
- 信号能触发订单（模拟盘）

**技术路径**：
```
1. 设计 QCAlgorithm 基类接口
   ↓
2. 实现策略生命周期管理
   ↓
3. 实现 Portfolio/Account 属性
   ↓
4. 实现交易 API（MarketOrder 等）
   ↓
5. 实现技术指标（SMA）
   ↓
6. 编写 SMA 策略示例
   ↓
7. 运行策略并下单验证
```

**需要实现的模块**：
- `src/strategy/base.py`：QCAlgorithm 基类
- `src/strategy/indicators.py`：技术指标
- `src/strategy/examples/sma_crossover.py`：SMA 策略
- `src/engine/live_engine.py`：实盘引擎（简化版）

**复用切片1-2**：
- ✅ 数据接入
- ✅ 数据库
- ✅ 订单管理
- ✅ 持仓跟踪

**输出物**：
```python
# 策略代码示例
class SMACrossover(QCAlgorithm):
    def Initialize(self):
        self.AddEquity("AAPL", Resolution.Daily)
        self.sma20 = self.SMA("AAPL", 20)
        self.sma60 = self.SMA("AAPL", 60)
    
    def OnData(self, slice):
        if not self.sma20.IsReady:
            return
        
        if self.sma20.Current.Value > self.sma60.Current.Value:
            self.MarketOrder("AAPL", 100)
```

## 五、切片执行模板

每个切片的标准流程：

### Day 1：切片启动
```
1. 复习切片目标和验收标准
2. 列出需要实现的文件清单
3. 设计核心接口（函数签名、类结构）
4. 创建文件骨架
```

### Day 2-4：核心开发
```
1. 实现核心功能
2. 边写边测试
3. 每天至少提交一次代码
4. 遇到问题及时调整
```

### Day 5：验收和演示
```
1. 运行验收标准
2. 补充遗漏的功能

4. 更新文档

```
