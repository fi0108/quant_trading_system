# 代码审查标准（Code Review Standard）

**版本**: v1.0  
**创建时间**: 2026-08-25  
**适用范围**: 所有阶段开发完成后的代码审查

**目的**: 确保代码质量、架构一致性、文档同步

---

## 📋 审查分类

代码审查分为**6大类**，每类包含多个检查项：

1. [架构一致性审查](#一架构一致性审查)
2. [代码规范审查](#二代码规范审查)
3. [功能完整性审查](#三功能完整性审查)
4. [测试质量审查](#四测试质量审查)
5. [文档同步审查](#五文档同步审查)
6. [安全与性能审查](#六安全与性能审查)

## 一、架构一致性审查

### 1.1 目录结构审查

**检查项**：
- [ ] 所有模块放置在正确的目录下
- [ ] 目录结构与架构设计文档一致
- [ ] 没有孤立文件或临时文件
- [ ] 目录命名符合规范（snake_case）

**检查方法**：
```bash
# 1. 对比目录结构
tree src/ -L 2 > /tmp/actual_structure.txt
# 与架构设计文档中的目录结构对比

# 2. 查找孤立文件
find src/ -maxdepth 1 -type f -name "*.py"

# 3. 查找临时文件
find . -name "*.tmp" -o -name "*.bak" -o -name "*~"
```

**评分标准**：
- ✅ 完全一致：5分
- ⚠️ 有1-2个偏差：3分
- ❌ 结构混乱：0分

---

### 1.2 模块职责审查

**检查项**：
- [ ] 每个模块职责单一明确
- [ ] 没有功能重复的模块
- [ ] 模块边界清晰
- [ ] 跨模块调用通过公开接口

**检查方法**：
```bash
# 1. 检查是否有功能重复的类
grep -rn "class.*Manager" src/ --include="*.py"
grep -rn "class.*Client" src/ --include="*.py"
grep -rn "class.*Handler" src/ --include="*.py"

# 2. 检查跨模块私有调用
grep -rn "from .* import _" src/ --include="*.py"
```

**评分标准**：
- ✅ 职责清晰无重复：5分
- ⚠️ 有1-2处重复：3分
- ❌ 职责混乱：0分

---

### 1.3 依赖关系审查

**检查项**：
- [ ] 没有循环依赖
- [ ] 依赖层次清晰（底层→上层）
- [ ] 公共模块不依赖业务模块
- [ ] 依赖关系与架构图一致

**检查方法**：
```bash
# 1. 检查common模块是否依赖业务模块
grep -rn "from data\|from trading\|from strategy" src/common/ --include="*.py"
# 应该返回空

# 2. 检查导入关系
# 使用pydeps或手动检查
grep -rn "^from\|^import" src/ --include="*.py" | grep -v "test"
```

**评分标准**：
- ✅ 依赖清晰无循环：5分
- ⚠️ 有轻微问题：3分
- ❌ 有循环依赖：0分

---

### 1.4 接口一致性审查

**检查项**：
- [ ] 同类接口风格一致
- [ ] 命名符合约定
- [ ] 参数顺序合理
- [ ] 返回类型一致

**检查方法**：
```bash
# 检查Manager类的接口风格
grep -A 5 "class.*Manager" src/ --include="*.py"
```

**评分标准**：
- ✅ 接口风格统一：5分
- ⚠️ 有个别不一致：3分
- ❌ 风格混乱：0分

---

## 二、代码规范审查

### 2.1 导入规范审查（重要！）

**检查项**：
- [ ] 所有导入使用相对路径（无src.前缀）
- [ ] 导入顺序正确（标准库→第三方→本地）
- [ ] 没有未使用的导入
- [ ] 导入语句分组清晰

**检查方法**：
```bash
# 1. 检查src.前缀（必须为空）
grep -rn "from src\." . --include="*.py" --exclude-dir=venv --exclude-dir=.git

# 2. 检查导入顺序（手动检查几个关键文件）
head -30 src/data/ibkr_client.py
head -30 src/strategy/qc_algorithm.py

# 3. 使用isort检查
isort --check-only src/
```

**评分标准**：
- ✅ 完全符合规范：5分
- ⚠️ 有少量src.前缀：3分
- ❌ 大量违规：0分

---

### 2.2 命名规范审查

**检查项**：
- [ ] 文件名：snake_case
- [ ] 类名：PascalCase
- [ ] 函数名：snake_case
- [ ] 常量名：UPPER_CASE
- [ ] 私有方法：_method

**检查方法**：
```bash
# 1. 检查文件名（应该都是小写+下划线）
find src/ -name "*.py" | grep -E "[A-Z]"
# 应该返回空

# 2. 检查类名（抽样检查）
grep -rn "^class [a-z]" src/ --include="*.py"
# 应该返回空（类名首字母应该大写）

# 3. 检查常量（抽样检查）
grep -rn "^[A-Z_]* =" src/ --include="*.py" | head -20
```

**评分标准**：
- ✅ 完全符合：5分
- ⚠️ 有少量偏差：3分
- ❌ 大量违规：0分

---

### 2.3 代码风格审查

**检查项**：
- [ ] 缩进一致（4空格）
- [ ] 行长度 < 120字符
- [ ] 空行使用合理
- [ ] 注释清晰有效

**检查方法**：
```bash
# 使用flake8检查
flake8 src/ --max-line-length=120 --statistics

# 或pylint
pylint src/ --max-line-length=120
```

**评分标准**：
- ✅ 无警告：5分
- ⚠️ <10个警告：3分
- ❌ >10个警告：0分

---

### 2.4 文档字符串审查

**检查项**：
- [ ] 所有公开类有文档字符串
- [ ] 所有公开方法有文档字符串
- [ ] 包含参数说明
- [ ] 包含返回值说明
- [ ] 包含使用示例（重要类）

**检查方法**：
```bash
# 检查缺少文档字符串的公开类/方法
# 手动抽查关键模块
grep -A 10 "^class " src/data/ibkr_client.py
grep -A 10 "def [^_]" src/data/ibkr_client.py
```

**评分标准**：
- ✅ 完整文档：5分
- ⚠️ 部分缺失：3分
- ❌ 大量缺失：0分

## 三、功能完整性审查

### 3.1 交付物清单审查

**检查项**：
- [ ] 所有计划模块已实现
- [ ] 核心功能已实现
- [ ] Demo脚本可运行
- [ ] 配置文件完整

**检查方法**：
```bash
# 1. 对比架构设计中的模块清单
# 手动检查每个模块是否存在

# 2. 运行Demo
python scripts/demo/quick_test.py --help
python scripts/demo/run_integrated_demo.py --help

# 3. 检查配置文件
ls -la config/
cat config/config.yaml
```

**评分标准**：
- ✅ 全部完成：5分
- ⚠️ 缺少非核心功能：3分
- ❌ 缺少核心功能：0分

---

### 3.2 功能正确性审查

**检查项**：
- [ ] 核心功能逻辑正确
- [ ] 边界条件处理正确
- [ ] 异常处理完善
- [ ] 日志记录完整

**检查方法**：
```bash
# 1. 检查异常处理
grep -rn "try:" src/ --include="*.py" | wc -l
grep -rn "except.*:" src/ --include="*.py" | wc -l
# 应该数量相当

# 2. 检查日志
grep -rn "logger\." src/ --include="*.py" | wc -l
# 应该有足够的日志

# 3. 检查TODO/FIXME
grep -rn "TODO\|FIXME" src/ --include="*.py"
```

**评分标准**：
- ✅ 功能正确完善：5分
- ⚠️ 有小问题：3分
- ❌ 有严重bug：0分

---

### 3.3 配置与硬编码审查

**检查项**：
- [ ] 没有硬编码配置
- [ ] 所有配置通过config获取
- [ ] 配置有默认值
- [ ] 敏感信息不在代码中

**检查方法**：
```bash
# 1. 检查硬编码IP/端口
grep -rn "127\.0\.0\.1\|localhost" src/ --include="*.py" | grep -v "default"
grep -rn "7497\|4002" src/ --include="*.py" | grep -v "default"

# 2. 检查是否使用config
grep -rn "config\.get" src/ --include="*.py" | wc -l

# 3. 检查敏感信息
grep -rn "password\|secret\|token" src/ --include="*.py"
```

**评分标准**：
- ✅ 完全配置化：5分
- ⚠️ 有少量硬编码：3分
- ❌ 大量硬编码：0分

## 四、测试质量审查

### 4.1 测试覆盖率审查

**检查项**：
- [ ] 单元测试覆盖率 > 85%
- [ ] 核心模块覆盖率 > 90%
- [ ] 关键路径有测试
- [ ] 边界条件有测试

**检查方法**：
```bash
# 运行覆盖率测试
pytest tests/ --cov=src --cov-report=term --cov-report=html

# 查看覆盖率报告
open htmlcov/index.html
```

**评分标准**：
- ✅ 覆盖率 > 85%：5分
- ⚠️ 覆盖率 70-85%：3分
- ❌ 覆盖率 < 70%：0分

---

### 4.2 测试质量审查

**检查项**：
- [ ] 测试用例清晰
- [ ] 测试独立（不依赖顺序）
- [ ] Mock外部依赖
- [ ] 测试命名清晰

**检查方法**：
```bash
# 1. 检查测试命名
grep -rn "def test_" tests/ --include="*.py" | head -20

# 2. 检查Mock使用
grep -rn "Mock\|patch" tests/ --include="*.py" | wc -l

# 3. 运行测试
pytest tests/ -v
```

**评分标准**：
- ✅ 测试质量高：5分
- ⚠️ 部分测试质量低：3分
- ❌ 测试质量差：0分

---

### 4.3 集成测试审查

**检查项**：
- [ ] 有Demo脚本
- [ ] Demo可以运行
- [ ] 覆盖核心流程
- [ ] 输出清晰

**检查方法**：
```bash
# 运行所有Demo
python scripts/demo/quick_test.py
python scripts/demo/run_integrated_demo.py --help
```

**评分标准**：
- ✅ Demo完整可运行：5分
- ⚠️ Demo部分可运行：3分
- ❌ Demo不能运行：0分

---

### 4.4 端到端测试审查（重要！）

**检查项**：
- [ ] 有完整的端到端测试场景
- [ ] 测试真实数据流
- [ ] 测试异常恢复
- [ ] 测试稳定性（长时间运行）

**检查场景**：
1. **正常交易流程**：连接 → 订阅数据 → 策略计算 → 风控检查 → 下单 → 持仓更新
2. **异常恢复**：断线重连、数据缺失处理、订单失败处理
3. **稳定性**：连续运行30分钟无错误
4. **完整性**：所有模块集成工作

**检查方法**：
```bash
# 1. 查看测试目录结构
tree tests/

# 2. 检查是否有端到端测试
find tests/ -name "*integration*" -o -name "*e2e*"

# 3. 运行Demo验证
python scripts/demo/run_integrated_demo.py --symbol AAPL --duration 60
```

**评分标准**：
- ✅ 有完整端到端测试：5分
- ⚠️ 有部分端到端测试：3分
- ❌ 缺少端到端测试：0分

## 六、安全与性能审查

### 6.1 安全审查

**检查项**：
- [ ] 没有硬编码密码
- [ ] 敏感信息加密
- [ ] 输入验证完整
- [ ] SQL参数化查询

**检查方法**：
```bash
# 1. 检查敏感信息
grep -rn "password.*=.*['\"]" src/ --include="*.py"

# 2. 检查SQL注入风险
grep -rn "execute.*%\|execute.*format" src/ --include="*.py"

# 3. 检查输入验证
grep -rn "def.*request\|def.*input" src/ --include="*.py" -A 5
```

**评分标准**：
- ✅ 无安全问题：5分
- ⚠️ 有小问题：3分
- ❌ 有严重安全隐患：0分

---

### 6.2 性能审查

**检查项**：
- [ ] 没有明显性能问题
- [ ] 资源使用合理
- [ ] 有性能关键路径优化
- [ ] 没有内存泄漏

**检查方法**：
```bash
# 1. 检查循环效率
grep -rn "for.*in.*range" src/ --include="*.py"

# 2. 检查资源释放
grep -rn "close()\|cleanup()" src/ --include="*.py"

# 3. 运行性能测试（如有）
pytest tests/ -k "performance"
```

**评分标准**：
- ✅ 性能良好：5分
- ⚠️ 有小问题：3分
- ❌ 有严重性能问题：0分
