**文档版本**：v1.0  
**创建日期**：2026-08-14  
**文档状态**：✅ 已完成  
**适用阶段**：开发启动前的准备工作  
**预计耗时**：5-8 小时

## 文档说明

本文档提供**垂直开发模式**下的完整准备工作流程，确保开发过程中不会遗漏 MVP 文档中的任何功能点。

**核心目标**：
1. 从 MVP 文档中系统性提取所有功能点（约 80+ 个）
2. 设计 6-8 个垂直切片，覆盖所有功能点
3. 建立功能追踪表格，实时跟踪开发进度
4. 确保无遗漏、无冲突

**基于文档**：
- [MVP 核心模块清单](../design/3_MVP核心模块清单.md)
- [架构核心模块分析](../design/2架构核心模块分析.md)

---

## 为什么需要这个流程？

### 垂直开发的遗漏风险

**常见遗漏场景**：
1. **横向遗漏**：某个模块的功能点被跳过
   - 例如：实现了订单提交，但忘了订单幂等性

2. **纵向遗漏**：某个功能层级被跳过
   - 例如：实现了正常流程，但忘了异常处理

3. **非功能性遗漏**：验收标准、边界条件被忽略
   - 例如：功能实现了，但没有日志、没有测试

4. **隐式依赖遗漏**：切片之间的依赖关系不清晰
   - 例如：切片 3 依赖切片 1 的某个功能，但切片 1 没实现

### 三层保障机制

本流程通过三层机制保障无遗漏：

```
机制 1：功能点全量提取
    ↓
机制 2：功能覆盖矩阵
    ↓
机制 3：检查清单验证
```

## 完整工作流程（5 个步骤）

### 📋 流程总览

```
步骤 1：创建功能点追踪表格（工具准备）30 分钟
   ↓

   ↓
步骤 5：最终检查（确保无遗漏）30 分钟
```

## 步骤 1：创建功能点追踪表格（30 分钟）

### 目标
搭建追踪工具的框架

### 工具选择
- **推荐**：Google Sheets（云端协作、随时访问）
- **备选**：Excel（本地、离线工作）
- **备选**：Notion/飞书文档（可视化更好）

### 创建 4 个 Sheet

#### Sheet 1：功能点清单（主表）

**列名设计**：
```
A列: 功能点ID (如 F1.1, F1.2, NFR1.1, R1)
B列: 所属模块 (如 数据层、策略引擎)
C列: 功能点描述 (简短描述)
D列: 优先级 (P0/P1/P2)
E列: 负责切片 (如 切片1、切片3)
F列: 完成度目标 (60%/80%/100%)
G列: 实际完成度 (开发中更新)
H列: 状态 (📅 Planned / 🔄 In Progress / ✅ Done / ⚠️ Blocked)
I列: 备注 (记录问题、依赖等)
```

**模板示例**：
| 功能点ID | 所属模块 | 功能点描述 | 优先级 | 负责切片 | 完成度目标 | 实际完成度 | 状态 | 备注 |
|---------|---------|-----------|-------|---------|-----------|-----------|------|------|
| F1.1 | 数据层 | 实时行情订阅 | P0 | 切片1 | 100% | 0% | 📅 Planned | |
| F1.2 | 数据层 | 历史数据存储 | P0 | 切片1 | 60% | 0% | 📅 Planned | 复杂查询待后续切片 |
| F1.3 | 数据层 | Redis 缓存 | P0 | 切片3 | 100% | 0% | 📅 Planned | |

#### Sheet 2：功能覆盖矩阵

**结构设计**：
```
第一列：功能点ID
第一行：切片1, 切片2, ..., 切片8, 最终覆盖
每个单元格：✅ 100% / ⚠️ 60% / - (不涉及)
```

**模板示例**：
| 功能点ID | 切片1 | 切片2 | 切片3 | 切片4 | 切片5 | 切片6 | 切片7 | 切片8 | 最终覆盖 |
|---------|------|------|------|------|------|------|------|------|---------|
| F1.1 | ✅ 100% | - | - | - | - | - | - | - | ✅ 100% |
| F1.2 | ⚠️ 60% | - | - | ✅ 100% | - | - | - | - | ✅ 100% |
| F1.3 | - | - | ✅ 100% | - | - | - | - | - | ✅ 100% |

**图例说明**：
- ✅ 100% = 该切片完整实现此功能点
- ⚠️ 60-90% = 该切片部分实现（需在备注说明未实现部分）
- `-` = 该切片不涉及此功能点
- 最后一列"最终覆盖"应该全部是 ✅ 100%

## 步骤 3：设计切片方案（1-2 小时）

### 目标
基于功能点清单，设计 6-8 个垂直切片

### 切片设计原则

**原则 1：端到端价值**
- 每个切片必须产出可演示的业务价值
- 不能是"只实现了一个类但跑不起来"

**原则 2：依赖最小化**
- 尽量减少对未完成切片的依赖
- 可以用简化实现、Mock 对象代替

**原则 3：风险前置**
- 高风险、高不确定性的功能尽早验证
- 核心交易路径优先于边缘功能

**原则 4：迭代完善**
- 同一个功能点可以在多个切片中逐步完善
- 第一次实现 60%，第二次补充到 90%，第三次达到 100%

---

### 设计方法

#### 方法 1：从核心交易路径出发（推荐）

**核心路径**：数据 → 策略 → 风控 → 下单 → 跟踪 → 持仓 → 监控

**切片设计**：
```
切片 1：打通"数据接入"（数据层）
切片 2：打通"策略回测"（数据 → 策略 → 回测）
切片 3：打通"风控检查"（策略 → 风控）
切片 4：打通"回测完善 + 可视化"（回测优化）
切片 5：打通"模拟下单"（策略 → 风控 → 下单）
切片 6：打通"持仓管理"（下单 → 跟踪 → 持仓）
切片 7：打通"监控告警"（全流程监控）
切片 8：打通"完善风控"（持仓 → 止损止盈）
```

---

#### 方法 2：从风险点出发

查看 Sheet 4 的风险点，确保每个风险都有切片覆盖：

```
R1 重复下单 → 切片 3（风控检查切片）
R2 状态不同步 → 切片 6（持仓管理切片）
R3 风控失效 → 切片 3（风控检查切片）
R4 断线未恢复 → 切片 7（监控告警切片）
```

---

#### 方法 3：从依赖关系出发

**依赖分析**：
```
数据层 ─→ 策略引擎 ─→ 回测引擎
   └──────→ 实盘引擎 ─→ 订单管理 ─→ 仓位管理
                └─→ 风控 ──────────┘
                
监控告警 ←─────────────────────── 所有模块
```

**切片顺序**（按依赖关系）：
1. 切片 1（数据层）- 无依赖
2. 切片 2（策略 + 回测）- 依赖切片 1
3. 切片 3（风控）- 依赖切片 2
4. 切片 4（回测完善）- 依赖切片 2, 3
5. 切片 5（实盘 + 下单）- 依赖切片 1, 3
6. 切片 6（持仓管理）- 依赖切片 5
7. 切片 7（监控告警）- 依赖切片 1-6
8. 切片 8（完善风控）- 依赖切片 6, 7

### Q1：如果开发过程中发现新的功能点怎么办？

1. 立即添加到 Sheet 1（功能点清单）
2. 评估是否属于 MVP 范围（对照 MVP 文档的"MVP 边界"）

4. 更新 Sheet 2（功能覆盖矩阵）

### Q2：如果某个切片延期了怎么办？
**A**：
1. 评估是否影响后续切片（查看 Sheet 3 的依赖关系）
2. 如果影响，调整后续切片的开始日期
3. 如果不影响，继续后续切片，延期的切片后续补完
4. 更新 Sheet 3 的预计完成日期

---

### Q3：如果发现某个功能点无法在当前切片完成怎么办？
**A**：
1. 记录原因（技术难度、依赖未满足等）
2. 降低本切片的完成度目标（如从 100% 降到 60%）
3. 在后续切片中补充
4. 更新 Sheet 1 和 Sheet 2

**示例**：
- 原计划：切片 1 完成 F1.2（历史数据存储）100%

- 调整：切片 1 完成 60%，剩余 40% 分配到切片 4
- 更新表格：
  - Sheet 1：F1.2 负责切片改为"切片1, 切片4"，完成度目标改为"60% → 100%"
  - Sheet 2：F1.2 在切片1列改为 ⚠️ 60%，在切片4列标注 ✅ 100%

## 避免常见错误

### ❌ 错误 1：跳过步骤 1，直接提取功能点
**后果**：没有结构化的地方存储，容易遗漏  
**避免**：先搭好框架，再填充内容

---

### ❌ 错误 2：提取功能点时只看"核心功能"，忽略验收标准和风险点
**后果**：遗漏隐含功能点  
**避免**：系统性扫描每个模块的所有章节（核心功能、验收标准、关键风险、关键设计）

---

### ❌ 错误 3：切片设计时不考虑依赖关系
**后果**：后续切片无法开始（依赖未满足）  
**避免**：画出依赖关系图，按拓扑排序设计切片

---

### ❌ 错误 4：功能覆盖矩阵填写后不检查
**后果**：有遗漏但不知道  
**避免**：必须执行步骤 5 的检查

---

### ❌ 错误 5：开发中不更新追踪表格
**后果**：表格与实际不符，失去追踪价值  
**避免**：每天或每个功能点完成后立即更新

---

## 总结

### 核心理念

> **"可见即可控"**
> 
> 把所有功能点显式列出来，把覆盖关系可视化，
> 就不会有遗漏的风险。
> 
> **垂直开发 + 功能追踪 = 既有迭代速度，又有覆盖保障**

---

### 三大保障机制回顾

```
1. 功能点全量提取
   → 确保所有功能点都被识别（83 个）

2. 功能覆盖矩阵
   → 确保每个功能点至少被一个切片覆盖
   → 可视化完成度，一目了然

3. 检查清单机制
   → 切片开始前检查（规划）
   → 切片完成后检查（验证）
   → 阶段性全量检查（扫描遗漏）
```

---

### 立即开始

**行动清单**：
```
□ 今日任务：创建功能点追踪表格（30 分钟）
□ 明日任务：功能点全量提取（2-3 小时）
□ 后天任务：设计切片 + 填写矩阵（2-4 小时）
□ 第四天：最终检查 + 开始切片 1
```
