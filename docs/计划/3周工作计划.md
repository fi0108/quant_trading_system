风控层（35%→65%）
本周新增功能
1. 止损监控（核心功能）

功能：持仓亏损达到阈值自动平仓
触发条件：
亏损比例：(当前价 - 成本价) / 成本价 < -5%
检查频率：每次收到新Bar数据
处理流程：
检测到触发 → 生成卖出信号
标记：止损订单（优先级高）
下单类型：限价单（追踪3次）→ 市价单（确保成交）
日志：打印"触发止损：AAPL，亏损-5.2%"
告警：发送邮件通知
2. 止盈监控

功能：持仓盈利达到阈值自动平仓
触发条件：
盈利比例：(当前价 - 成本价) / 成本价 > 10%
检查频率：每次收到新Bar数据
处理流程：
检测到触发 → 生成卖出信号
标记：止盈订单（优先级中）
下单类型：限价单
日志：打印"触发止盈：TSLA，盈利+12.3%"
3. 当日亏损限制

功能：当日亏损达到总资金2%停止新开仓
计算逻辑：
当日亏损 = 所有已实现亏损 + 所有未实现亏损
亏损比例 = 当日亏损 / 账户总资金
触发条件：亏损比例 >= 2%
处理流程：
设置标志：daily_loss_limit_triggered = True
拒绝新开仓（买入信号）
允许平仓（卖出信号）
日志：打印"触发当日亏损限制，停止开仓"
告警：发送邮件通知
重置时机：每天00:00或系统启动时检查日期变化
4. 波动率熔断（可选）

功能：标的波动率过高暂停交易
触发条件：
1分钟涨跌幅 > 15%（极端情况）
或5分钟涨跌幅 > 20%
处理流程：
暂停该标的所有交易（买入和卖出）
持续时间：5分钟
日志：打印"AAPL波动率异常，暂停交易"
告警：发送邮件
不实现

关键设计决策
决策1：止损阈值的选择

选择：-5%
理由：
太紧（如-2%）：容易被正常波动触发
太松（如-10%）：亏损太大才止损
-5%：平衡风险和策略空间
个股差异：第4周可以根据波动率动态调整
决策2：止盈阈值的选择

选择：+10%
理由：
止盈/止损比例：2:1（符合经典风控）
给盈利空间：不要过早止盈
锁定利润：避免大幅回撤
决策3：当日亏损限制

选择：2%
理由：
保护本金：避免单日重大损失
20天连续亏损2% ≈ 33%总亏损（可接受范围）
给策略机会：不是一天亏损就停止所有交易
决策4：止损的下单类型

优先：限价单（追踪3次）
备选：市价单（确保成交）
理由：止损是风控底线，必须成交

关键决策总结
决策1：异常恢复 vs 系统停止
选择：尽量恢复，最后才停止

恢复优先级

连接断开 → 自动重连（5次）
数据异常 → 跳过，继续运行
订单拒绝 → 记录，不重试
重连失败 → 停止系统，发送告警
理由

量化交易需要持续运行
暂时异常不应该停止系统
只有严重错误才停止
决策2：止损优先级最高
选择：止损必须执行

实现方式

限价单追踪3次
仍不成交 → 改用市价单
确保：止损100%执行
理由

止损是风控底线
宁可多损失滑点，也要止损
非止损订单可以放弃
决策3：对账以IBKR为准
选择：发现差异时，本地同步到IBKR

理由

IBKR是实际持仓的权威
本地可能因bug导致不准
自动修正+人工告警
例外

如果IBKR数据明显错误（如持仓为负数）
不自动修正，发送紧急告警
人工介入处理
决策4：日志和数据库的分工
日志：瞬时事件、调试信息

优点：快速写入，易于查看
缺点：不便于查询统计
数据库：结构化数据、历史记录

优点：便于查询、统计、分析
缺点：写入相对慢
分工

日志：记录所有事件（DEBUG级别）
数据库：只记录关键数据（订单、持仓、系统事件）
日志30天后删除，数据库长期保留
决策5：邮件告警的频率
P0告警：立即发送

止损、止盈、连接失败等
P1告警：汇总发送（每小时）

避免：短时间内大量邮件
汇总：1小时内的P1事件合并成1封邮件
P2信息：不发送

只记录日志
风险和应对
风险1：数据库连接失败
现象

系统启动时无法连接数据库
运行中数据库连接断开
应对

启动时检查数据库连接
连接失败：打印错误，停止启动
运行中断开：尝试重连（3次）
重连失败：切换到"降级模式"
只使用内存存储
日志记录所有操作
事后手动恢复数据
优先级：高（阻塞启动）

风险2：邮件发送失败
现象

告警邮件发送失败
SMTP连接超时
应对

捕获异常：不因邮件失败而崩溃
记录日志：邮件发送失败，内容是什么
重试机制：失败后30秒重试1次
降级方案：
写入本地文件：alerts/alert_YYYYMMDD_HHMMSS.txt
事后手动查看
优先级：中（不影响交易）

风险3：止损订单不成交
现象

止损限价单追踪3次仍不成交
市价单也不成交（极端情况，如停牌）
应对

限价追踪3次后改市价单
市价单提交后持续跟踪
如果10分钟仍未成交：
查询IBKR该标的状态（是否停牌）
发送紧急告警邮件
人工介入处理
优先级：高（风控失效）

风险4：系统时间不准
现象

服务器时间与真实时间不同步
导致：交易日判断错误、定时任务触发错误
应对

启动时检查系统时间
与IBKR服务器时间对比
如果差异>10秒：
打印警告
发送告警邮件
建议同步时间（使用NTP）
优先级：中（影响定时任务）

风险5：磁盘空间不足
现象

日志文件越来越大
数据库越来越大
磁盘空间不足
应对

启动时检查磁盘空间
如果剩余<1GB：打印警告
定期清理：
日志：30天前的删除
数据库：1年前的归档
监控：每天检查磁盘使用
优先级：低（可提前预防）
