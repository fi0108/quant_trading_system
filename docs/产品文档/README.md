## 文档使用说明

### 产品需求文档四要素
每个模块的需求文档必须包含：
1. **输入输出**：明确数据流入流出
2. **核心逻辑**：1-3句话描述关键算法
3. **边界条件**：异常场景如何处理
4. **验收标准**：2-3个可测试案例

### 阅读顺序
1. 新成员：先读总需求文档 → 再读具体模块
2. 开发前：产品需求文档 → 开发文档 → 测试文档
3. Bug修复：先查产品需求，确认预期行为

### 更新规范
- 需求变更：更新产品文档 + 同步通知开发和测试
- 版本记录：重大变更在文档底部记录变更历史
