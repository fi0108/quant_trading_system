# 模块一：市场数据接入 - 需求文档 v3.0

## 1. 核心目标

本模块为量化交易系统提供数据基础设施，支持两大核心场景：

1. **历史数据同步**：为策略回测和验证提供数据支持
2. **实时数据同步**：为已验证策略提供实时监控数据

## 2. 核心功能

### 2.1 历史数据同步

**功能描述**：从 Interactive Brokers (IBKR) 获取指定股票的历史数据，存储到 PostgreSQL，供回测引擎查询分析。

**参数设置**：
- `symbols`：股票代码列表（必填），例如：`['AAPL', 'TSLA', 'GOOGL']`
- `start_date`：开始日期（可选），格式：`YYYY-MM-DD`
- `end_date`：结束日期（可选），格式：`YYYY-MM-DD`
- `granularity`：数据粒度（可选），选项：`minute`、`hour`、`day`、`week`、`month`

**默认行为**：
- 未指定时间范围时，默认同步最近 **6 个月**数据
- 未指定粒度时，默认同步 **日线数据**

**使用场景**：
```bash
# 同步 AAPL 最近 6 个月日线数据
python scripts/sync_historical_data.py --symbols AAPL

# 同步 TSLA 指定时间段的分钟数据
python scripts/sync_historical_data.py --symbols TSLA --start-date 2025-01-01 --end-date 2025-06-30 --granularity minute

# 同步多只股票
python scripts/sync_historical_data.py --symbols AAPL,TSLA,GOOGL --granularity day
```

### 2.2 实时数据同步

**功能描述**：订阅 IBKR 实时数据流，将数据写入 Redis（最新数据缓存）和 PostgreSQL（持久化存储），供已验证策略实时监控。

**运行模式**：
- 程序持续运行，自动订阅指定股票的实时数据
- 交易时段（盘前、盘中、盘后）接收数据并写入数据库
- 非交易时段自动进入休眠状态

**数据流向**：
- **Redis**：存储最新 N 条 K 线数据（快速访问）
- **PostgreSQL**：持久化所有实时数据（历史查询）

**使用场景**：
```bash
# 启动实时数据同步服务
python src/connection/market_data_service.py --symbols AAPL,TSLA --granularity minute
```

## 3. 数据粒度支持

| 粒度 | 说明 | 典型应用场景 |
|------|------|-------------|
| **分钟** | 1 分钟 K 线 | 日内短线策略、高频交易 |
| **小时** | 1 小时 K 线 | 日内波段策略 |
| **日** | 日 K 线 | 中短期趋势策略（几天到几周） |
| **周** | 周 K 线 | 中期趋势策略（几周到几个月） |
| **月** | 月 K 线 | 长期趋势策略（几个月以上） |

## 4. 特殊场景处理

### 4.1 时区处理

- **IBKR 数据时间**：美国东部时间 (US/Eastern)
- **系统存储时间**：UTC 标准时间
- **用户展示时间**：可配置（默认本地时区）

所有数据库存储统一使用 UTC，查询时根据需要转换。

### 4.2 交易日历

- 自动识别美股交易日（工作日）
- 自动跳过节假日、非交易日
- 支持盘前交易（04:00-09:30 ET）、正常交易（09:30-16:00 ET）、盘后交易（16:00-20:00 ET）

### 4.3 数据回填

**场景**：程序停止运行期间缺失的数据

**处理方式**：
- 程序重启时自动检测数据缺口
- 调用历史数据接口回填缺失时段
- 回填完成后继续实时订阅

## 5. 数据存储

### 5.1 PostgreSQL 表结构

```sql
-- 分钟级数据表（示例）
CREATE TABLE market_data_1min (
    id BIGSERIAL PRIMARY KEY,
    symbol VARCHAR(20) NOT NULL,
    timestamp TIMESTAMP NOT NULL,
    open DECIMAL(12, 4) NOT NULL,
    high DECIMAL(12, 4) NOT NULL,
    low DECIMAL(12, 4) NOT NULL,
    close DECIMAL(12, 4) NOT NULL,
    volume BIGINT NOT NULL,
    session VARCHAR(20),  -- 'pre_market', 'regular', 'after_hours'
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_symbol_timestamp ON market_data_1min(symbol, timestamp DESC);
```

其他粒度（小时、日、周、月）表结构类似，表名分别为：
- `market_data_1hour`
- `market_data_daily`
- `market_data_weekly`
- `market_data_monthly`

### 5.2 Redis 缓存结构

```
key: {symbol}:latest_bars:{granularity}
value: List[JSON] (最新 100 条 K 线数据)

示例：
AAPL:latest_bars:minute -> [
    {"timestamp": "2026-08-10 09:31:00", "open": 150.5, "high": 150.8, ...},
    {"timestamp": "2026-08-10 09:32:00", "open": 150.7, "high": 151.0, ...},
    ...
]
```

## 6. 数据验证

所有写入数据库的数据需通过以下验证：
- `open`, `high`, `low`, `close` > 0
- `high` >= `low`
- `high` >= `open`, `close`
- `low` <= `open`, `close`
- `volume` >= 0

验证失败的数据记录到日志，不写入数据库。

## 7. 非功能性要求

- **可靠性**：网络异常时自动重连，重试机制
- **性能**：实时数据延迟 < 1 秒
- **可维护性**：日志记录所有关键操作、异常
- **可扩展性**：支持新增股票、新增粒度
