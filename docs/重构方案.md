# 项目目录重构方案

**文档版本**：v1.0  
**创建日期**：2026-08-22  
**重构原则**：基于垂直切片设计，消除功能重复，职责清晰

---

## 一、当前问题分析

### 🔴 **严重问题**

#### 1. **重复的 ibkr_client.py**
- `src/broker/ibkr_client.py` - 订单管理相关
- `src/connection/ibkr_client.py` - 市场数据相关
- **问题**：同一个 IBKR 连接被拆分到两个地方，职责不清

#### 2. **目录职责混乱**
- `broker/` - 订单、持仓、风控管理
- `connection/` - 连接管理、市场数据、存储、调度器
- **问题**：connection 目录承担了太多职责（连接+数据+存储+调度）

#### 3. **模块命名冲突**
- ✅ 已修复：`calendar` → `trading_calendar`

#### 4. **没有按切片组织**
- 当前是按技术层划分（broker/connection/strategy）
- 应该按业务功能划分（数据/交易/策略/回测）

## 五、模块职责定义

### **data/ - 数据模块**
**职责**：数据的获取、验证、存储  
**不负责**：交易逻辑、策略逻辑

**核心类**：
- `IBKRClient`：统一的IBKR连接客户端
- `RealtimeSubscriber`：实时数据订阅
- `HistoricalDownloader`：历史数据下载
- `DatabaseWriter`：数据库写入

**对外接口**：
```python
# 实时数据订阅
from data.realtime import RealtimeSubscriber
subscriber = RealtimeSubscriber(client)
subscriber.subscribe("AAPL", callback=on_bar)

# 历史数据下载
from data.historical import HistoricalDownloader
downloader = HistoricalDownloader(client)
bars = downloader.download("AAPL", start_date, end_date)
```

---

### **trading/ - 交易模块**
**职责**：连接管理、订单执行、持仓管理、风控  
**不负责**：数据获取、策略逻辑

**核心类**：
- `ConnectionManager`：连接生命周期管理
- `OrderManager`：订单管理
- `PositionManager`：持仓管理
- `RiskManager`：风险控制

**对外接口**：
```python
# 订单管理
from trading.order import OrderManager
order_mgr = OrderManager(client)
order_id = order_mgr.place_order("AAPL", 100, "BUY")

# 持仓管理
from trading.position import PositionManager
pos_mgr = PositionManager(client)
positions = pos_mgr.get_positions()
```

---

### **strategy/ - 策略模块**
**职责**：策略框架、技术指标、策略示例  
**不负责**：数据获取、订单执行细节

**核心类**：
- `QCAlgorithm`：策略基类
- `SMA/EMA`：技术指标
- 具体策略实现

**对外接口**：
```python
from strategy.base import QCAlgorithm

class MyStrategy(QCAlgorithm):
    def Initialize(self):
        self.AddEquity("AAPL")
        self.sma = self.SMA("AAPL", 20)
    
    def OnData(self, slice):
        if self.sma.IsReady:
            self.MarketOrder("AAPL", 100)
```

---

### **backtest/ - 回测模块**
**职责**：回测引擎、绩效分析、参数优化  
**不负责**：实盘交易

---

### **monitoring/ - 监控模块**
**职责**：系统监控、告警通知  
**不负责**：业务逻辑

---

### **scheduling/ - 调度模块**
**职责**：任务调度、交易日历
