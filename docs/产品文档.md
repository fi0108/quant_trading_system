个人量化交易平台产品需求文档（草稿）
模块一：市场数据接入
功能1.1：实时行情订阅
输入：股票代码列表、数据类型（Bar/Tick）
输出：实时行情数据流（价格、成交量、时间戳）
核心逻辑：通过IBKR API订阅指定标的行情，接收推送数据后存入Redis缓存（保留最近100根K线）+ 异步写入PostgreSQL
边界条件：

连接断开：记录断点时间，重连后继续订阅
无效代码：返回错误，记录日志，跳过该标的
数据延迟超过5秒：告警通知
验收标准：

案例1：订阅AAPL，1分钟内收到至少1条行情更新，Redis可查询
案例2：手动断开网络，30秒内自动重连成功
案例3：订阅无效代码"INVALID123"，返回错误不崩溃
功能1.2：历史数据拉取
输入：股票代码、起止日期、频率（日线/分钟线）
输出：DataFrame格式的历史数据（OHLCV）
核心逻辑：优先从本地数据库查询，缺失部分调用IBKR/AKShare API补全，合并后返回
边界条件：

API限流：每次请求间隔1秒，超限则排队等待
数据缺失：返回可用数据段，标记缺失时间段
日期超出范围：返回空DataFrame + 提示信息
验收标准：

案例1：拉取AAPL 2024-01-01至2024-12-31日线数据，返回完整252条记录
案例2：拉取不存在的未来日期，返回空数据 + 明确提示
案例3：本地已有数据，查询耗时<100ms
模块二：策略执行引擎
功能2.1：策略信号生成
输入：策略代码对象、当前行情数据、账户状态（持仓/资金）
输出：交易信号（BUY/SELL/HOLD、标的、目标数量）
核心逻辑：按定时周期（每分钟）调用策略的on_bar()方法，策略内部计算指标后生成信号
边界条件：

策略执行超时（>10秒）：强制中断，记录错误
策略抛异常：捕获后记录，跳过本次执行，不影响其他策略
无信号生成：返回HOLD，继续下一轮
验收标准：

案例1：简单均线策略，金叉时生成BUY信号，死叉时生成SELL信号
案例2：策略代码有语法错误，系统捕获异常不崩溃
案例3：5秒内完成一次信号计算
功能2.2：回测引擎
输入：策略代码、历史数据时间范围、初始资金、手续费率
输出：回测报告（总收益率、最大回撤、夏普比率、交易记录）
核心逻辑：逐Bar遍历历史数据，触发策略生成信号，按市价模拟成交（次Bar开盘价），计算持仓和资金变化
边界条件：

资金不足：拒绝买入订单，记录"资金不足"
持仓不足：拒绝卖出订单，记录"持仓不足"
数据缺失Bar：跳过该Bar，策略不触发
验收标准：

案例1：用2023年全年数据回测均线策略，返回收益率、回撤等指标
案例2：初始资金10万，买入1万股超出资金量，订单被拒绝
案例3：历史数据有缺失，回测能正常完成，标记跳过的时间点
模块三：风险控制
功能3.1：前置风控检查
输入：待下单信号（标的、方向、数量）、当前账户状态
输出：通过/拒绝 + 拒绝原因
核心逻辑：按顺序执行5项检查：①资金充足性 ②单票持仓限额（不超过总资金30%） ③单日交易次数（<20次） ④市场交易时间 ⑤策略启用状态
边界条件：

任一检查不通过：立即拒绝，返回具体原因
边界值（如持仓正好30%）：按通过处理
验收标准：

案例1：可用资金5万，下单买入10万，被拒绝"资金不足"
案例2：持有AAPL市值已达总资金35%，再买入被拒绝"持仓超限"
案例3：当天已交易20次，第21次被拒绝"交易频率超限"
功能3.2：止损止盈监控
输入：当前持仓列表、实时行情
输出：触发平仓信号的持仓列表
核心逻辑：每次行情更新时，计算每个持仓的浮动盈亏比例，达到止损阈值（-5%）或止盈阈值（+15%）时生成平仓信号
边界条件：

盈亏在阈值范围内：不触发
同时触发多个：按亏损优先顺序处理
验收标准：

案例1：持有AAPL成本100元，跌至94元，触发止损
案例2：持有TSLA成本200元，涨至230元，触发止盈
案例3：持仓盈亏-4.9%，不触发止损
模块四：订单管理
功能4.1：订单提交与跟踪
输入：订单对象（标的、方向、数量、类型）
输出：订单状态更新流（Submitted → Filled/Cancelled）
核心逻辑：

生成唯一订单ID，保存到数据库（状态：待提交）
调用IBKR API提交订单
监听订单状态回调，每次状态变化更新数据库
成交时更新持仓表
边界条件：

提交失败（网络错误）：重试1次，仍失败则标记"提交失败"
部分成交：更新已成交数量，保持订单活跃
订单被拒绝：记录拒绝原因，不重试
验收标准：

案例1：提交市价买单，10秒内状态变为Filled，持仓增加
案例2：限价单价格偏离市场，30秒未成交被撤单
案例3：手动从IBKR TWS撤单，本地状态同步更新为Cancelled
功能4.2：持仓对账
输入：本地持仓表、IBKR账户持仓
输出：差异报告（如有）
核心逻辑：每5分钟拉取IBKR持仓，逐个对比标的和数量，差异超过1股则告警
边界条件：

无差异：静默通过
差异<1股（精度问题）：记录日志，不告警
差异>1股：发送告警，人工介入
验收标准：

案例1：本地和IBKR持仓完全一致，对账通过无告警
案例2：手动从IBKR卖出10股，本地未同步，对账发现差异并告警
案例3：对账任务每5分钟自动执行一次
模块五：监控告警
功能5.1：系统健康监控
输入：系统运行状态（连接状态、错误日志、延迟）
输出：告警消息（邮件/钉钉/终端输出）
核心逻辑：每分钟检查：①IBKR连接状态 ②数据库连接 ③最近1分钟错误日志条数（>10条告警） ④行情延迟（>5秒告警）
边界条件：

连续3次检查失败：发送紧急告警
告警间隔：同类告警10分钟内只发1次
验收标准：

案例1：手动断开IBKR连接，1分钟内收到告警
案例2：数据库重启，恢复后告警自动解除
案例3：同一告警10分钟内不重复发送
功能5.2：账户风险监控
输入：账户当日盈亏、最大回撤、持仓集中度
输出：风险提示
核心逻辑：每10分钟计算：①当日亏损超过总资金2%告警 ②最大回撤>5%告警 ③单票持仓>40%告警
边界条件：

指标在安全范围：不触发
多个指标同时超限：合并为一条告警
验收标准：

案例1：当日亏损达2.5%，收到"当日亏损预警"
案例2：某票持仓占比45%，收到"持仓集中度过高"
案例3：账户正常运行，无告警骚扰
模块六：系统启动与恢复
功能6.1：系统启动流程
输入：配置文件（API凭证、策略列表、风控参数）
输出：系统就绪状态或启动失败提示
核心逻辑：

加载配置文件
连接数据库（PostgreSQL + Redis）
连接IBKR（重试3次，失败则退出）
从IBKR拉取当前持仓和未完成订单，与本地对账
订阅行情
启动策略调度器
进入主循环
边界条件：

配置文件缺失：提示"配置文件不存在"并退出
IBKR连接失败3次：发送告警，退出程序
持仓对账差异>10%：暂停策略，等待人工确认
验收标准：

案例1：正常启动，2分钟内进入运行状态，开始接收行情
案例2：IBKR未启动，系统提示连接失败并退出
案例3：本地持仓与IBKR差异大，系统暂停并告警
全局边界说明
并发限制：同一标的同时只能有1个活跃订单
日志记录：所有订单操作、风控拒绝、系统错误必须记录日志
幂等性：同一交易信号（相同标的+方向+时间戳前60秒内）只下单1次
超时设置：API调用超时10秒，数据库查询超时5秒
优雅退出：收到停止信号时，撤销所有未成交订单，保存状态后退出
