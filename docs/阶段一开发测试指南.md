阶段一：数据输入层 + 连接层开发指南
一、核心目标
建立与IBKR的稳定连接，实现行情数据的接收、验证、存储，确保系统能跨时区、跨Gateway重启稳定运行。

二、功能模块（按开发顺序）
模块1：时区管理器（优先）
功能：

统一时区转换（IBKR美东时间 ↔ UTC ↔ 上海本地时间）
自动识别夏令时（EST/EDT切换）
提供交易时段判断（基于美东时间）
核心接口：


ibkr_to_utc(时间) → UTC时间戳
utc_to_local(UTC时间) → 上海时间
utc_to_market(UTC时间) → 美东时间
is_trading_time(UTC时间) → 是否交易时段
next_market_close() → 下一收盘时间（UTC）
配置项：

市场时区：America/New_York
本地时区：Asia/Shanghai
交易时段：09:30-16:00（美东时间）

模块2：交易日历管理
功能：

加载并缓存美股交易日历（未来30天）
区分交易日/非交易日/半日市
支持手动导入CSV（应对临时休市）
数据来源：

优先使用 pandas_market_calendars 库
备用方案：CSV文件导入
存储：

PostgreSQL：trading_calendar 表
Redis缓存：key=trading_calendar:NYSE:{YYYYMM}
更新策略：

每月1日自动更新下月日历
启动时检查日历完整性

模块3：连接管理器
功能：

建立与IB Gateway的连接（TWS/Gateway地址配置）
心跳检测（每30秒）
连接状态管理（状态机）
状态机：


DISCONNECTED → CONNECTING → CONNECTED → READY
                    ↓            ↓
               [超时/失败]  [订阅完成]
                    ↓            
              CONNECTION_LOST → GATEWAY_RESTARTING
                    ↓                  ↓
               [立即重连]          [等待恢复]
重连策略：

指数退避：0秒 → 5秒 → 15秒 → 30秒 → 60秒
最大重试次数：10次
超过次数后告警并停止
关键决策：

使用 ib_insync 库封装IBKR原生API
连接超时：15秒
模块4：Gateway重启处理器
功能：

识别预定重启（美东时间03:00，重启窗口30分钟）
区分正常重启 vs 异常断线
重启期间暂停策略、缓存信号
重启窗口配置：


gateway_restart:
  scheduled_time: "03:00:00"  # 美东时间
  restart_window_minutes: 30  # 03:00-03:30
  pre_restart_prepare_minutes: 10  # 02:50开始准备
处理策略：

时间段	系统行为
02:50-03:00	停止接收新信号，等待订单完成，保存状态
03:00-03:30	断线不告警，标记GATEWAY_RESTARTING状态
03:30后重连	恢复订阅、状态对账、恢复策略
非窗口期断线	立即告警、快速重连
信号缓存：

重启期间信号写入 signal_buffer 表
恢复后检查信号有效期（默认10分钟）
有效信号执行，过期信号丢弃
模块5：数据订阅器
功能：

订阅实时行情（1分钟Bar/实时价格）
订阅账户数据（资金、持仓变化）
订阅订单状态（所有订单更新）
断线后自动恢复订阅
订阅类型（MVP）：

✅ 1分钟K线（reqRealTimeBars）
✅ 实时价格（Last/Bid/Ask）
✅ 账户余额和持仓
⏸️ Tick数据（后续版本）
⏸️ Level 2深度（后续版本）
订阅管理：

标的列表配置化（config/symbols.yaml）
单个标的订阅失败不影响其他
订阅确认超时：5秒
实时Bar处理：

只存储完成的Bar（Bar完成事件触发）
未完成的Bar缓存在Redis（供实时策略用）
避免同一时间戳重复写入
模块6：数据验证器
功能：

价格合理性检查（涨跌幅阈值）
时间戳连续性检查
数据完整性检查（字段非空非零）
重复数据去重
验证规则：


validation:
  max_price_change_percent: 0.20  # 单次最大涨跌20%
  max_bar_gap_minutes: 5          # 最大时间间隔5分钟
  min_volume: 0                   # 最小成交量（0表示不限）
异常处理：

轻微异常（单次跳点）：警告日志 + 前值填充
严重异常（价格为0/时间错误）：丢弃 + 错误日志
连续异常（连续3次失败）：暂停标的订阅 + 告警
模块7：数据存储器
功能：

实时数据写入Redis（同步）
历史数据写入PostgreSQL（异步批量）
统一使用UTC时间戳存储
存储架构：


[Redis] 热数据
  Key: {symbol}:latest_bars
  Value: 最新100根1分钟K线（JSON数组）
  TTL: 1小时
  写入: 同步立即写入

[PostgreSQL] 冷数据
  Table: market_data_1min
  Fields: symbol, timestamp(UTC), OHLCV, source
  Index: (symbol, timestamp)
  写入: 每10秒批量写入或累积100条
  分区: 按月自动分区（TimescaleDB）
数据来源标记：

realtime：实时订阅接收
historical：历史数据回填
backfill：检测缺口后回填
historical_corrected：数据对比后修正
写入容错：

PostgreSQL写入失败时，数据缓存在内存队列（最多1000条）
数据库恢复后自动重试
Redis可用即可保证实时策略运行
模块8：历史数据回填器
功能：

启动时检查数据完整性（基于交易日历）
批量下载历史数据（reqHistoricalData API）
限速控制（避免触发IBKR频率限制）
断点续传
回填策略：


启动时自动检查：
  1. 查询交易日历获取最近7个交易日
  2. 检查每个交易日的交易时段数据
  3. 发现缺口生成回填任务队列
  4. 限速下载（60请求/10分钟）
  5. 批量写入数据库（标记source='historical'）

运行中触发：
  • 实时数据连续缺失超过5分钟 → 触发回填
  • 每日收盘后检测当日数据完整性
限速控制：

IBKR限制：60个请求/10分钟
实现：令牌桶算法
每次请求消耗1个令牌，每10秒补充10个令牌
断点续传：

回填任务状态持久化（backfill_tasks表）
系统重启后继续未完成任务
模块9：数据质量检查器
功能：

每日收盘后对比实时数据与历史数据
识别差异并记录
显著差异自动修正
对比流程：


触发时间：美东16:30（收盘后30分钟）
对应上海时间：
  • 冬令时 05:30（次日）
  • 夏令时 04:30（次日）

流程：
  1. 拉取当日历史数据（reqHistoricalData）
  2. 与数据库实时数据逐条对比
  3. 计算差异百分比（价格/成交量）
  4. 记录到 data_quality_log 表
  5. 差异>0.5% → 更新为历史数据 + 告警
  6. 发现缺失 → 触发回填任务
差异阈值：


quality_check:
  price_diff_threshold: 0.005   # 0.5%
  volume_diff_threshold: 0.05   # 5%
  action_on_diff: "update"      # update/alert/ignore
