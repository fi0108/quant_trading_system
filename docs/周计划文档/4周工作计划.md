计算逻辑

基础指标

总收益率 = (期末资产 - 期初资产) / 期初资产
年化收益率 = 总收益率 × (365 / 运行天数)
最大回撤 = max((峰值资产 - 当前资产) / 峰值资产)
胜率 = 盈利交易次数 / 总交易次数
盈亏比 = 平均盈利金额 / 平均亏损金额
风险调整收益

夏普比率 = (年化收益率 - 无风险利率) / 年化波动率
索提诺比率 = (年化收益率 - 无风险利率) / 下行波动率
卡尔玛比率 = 年化收益率 / 最大回撤

缺点：计算量大，影响性能

优点：性能好
缺点：数据有延迟

缺点：实现复杂度高

决策4：多策略资金分配
选项A：共享资金池

优点：资金利用率高
缺点：策略之间会竞争资金，难以评估单策略表现
选项B：独立资金账户

优点：策略完全隔离，易于评估
缺点：资金利用率低
选项C：虚拟子账户（推荐）

优点：策略隔离但资金共享
缺点：需要资金调度逻辑
决策：选择C，虚拟子账户

理由

策略隔离是必须的：要知道哪个策略赚钱
资金利用率也很重要：总资金有限
虚拟子账户可以兼顾两者
实现方式


strategies:
  - name: ma_strategy
    capital: 50000  # 虚拟分配5万
  - name: rsi_strategy
    capital: 50000  # 虚拟分配5万
# 实际账户总资产10万，每个策略最多用5万
# 如果两个策略同时满仓，按比例缩减订单
资金调度规则

各策略有虚拟额度，独立计算盈亏
实际下单时检查总资金是否足够
不足时按虚拟额度比例分配实际资金
决策5：止损订单实现方式
选项A：客户端监控止损（当前方式）

优点：灵活，可自定义止损逻辑
缺点：依赖客户端运行，客户端崩溃止损失效
选项B：IBKR服务端止损单

优点：不依赖客户端，更安全
缺点：灵活性差，无法自定义
选项C：双保险（客户端+服务端）

优点：最安全
缺点：实现复杂，可能重复平仓
决策：选择C，双保险

理由

止损是风控核心，安全第一
客户端止损灵活（如ATR动态止损）
服务端止损兜底（客户端崩溃也能止损）
重复平仓问题可通过状态同步解决
实现方式

开仓时同时：
客户端记录止损价
IBKR下一个止损单（作为保险）
客户端止损触发时：
立即下单平仓
同时撤销IBKR止损单
如果客户端崩溃：
IBKR止损单自动触发
决策6：Redis使用范围
选项A：全面使用Redis（数据、状态、配置都用Redis）

优点：性能极致
缺点：架构复杂，增加依赖
选项B：只缓存热数据（最近1天的分钟数据）

优点：简单，收益明显
缺点：其他场景仍依赖数据库
选项C：不用Redis

优点：架构简单
缺点：历史数据查询慢
决策：选择B，只缓存热数据

理由

80%的查询是最近1天数据（回测、图表展示）
Redis缓存最近1天数据，命中率>80%
其他数据查询频率低，数据库够用
保持架构简单，Redis作为可选优化
缓存策略

缓存内容：最近1天的分钟级Bar数据
缓存更新：实时数据推送时同步写Redis

缓存预热：启动时加载最近1天数据
