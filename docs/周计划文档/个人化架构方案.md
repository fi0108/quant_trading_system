# 个人量化交易平台架构方案

## 架构简化策略

| 维度 | 企业版 | 个人版 | 简化理由 |
|------|--------|--------|----------|
| **券商接入** | 多券商插件化 | 仅 IBKR | 个人账户只需一个券商 |
| **数据源** | 多数据源聚合 | IBKR + yfinance 备用 | IBKR 提供实时和历史数据 |
| **消息队列** | Kafka/RabbitMQ | Redis Pub/Sub | 单机部署，Redis 足够 |
| **数据库** | 分布式集群 | PostgreSQL 单机 | 数据量小，单机即可 |
| **高可用** | 多节点冗余 | 单进程 + 日志监控 | 个人可接受短暂中断 |
| **用户系统** | 多租户隔离 | 无 | 仅自己使用 |

## 分层架构详细设计

### 1. Algorithm Layer（策略层）

#### 1.1 QCAlgorithm 基类

策略继承该基类后可无缝在回测和实盘间切换。

**生命周期方法**：

- **Initialize**
  - 设置初始资金、基准标的
  - 订阅交易标的和数据频率
  - 注册定时任务（盘前/盘中/盘后）
  - 初始化技术指标
  
- **OnData**
  - 数据到达时触发（Bar 或 Tick）
  - 接收标准化的数据结构
  - 策略逻辑主入口
  - 生成交易信号
  
- **OnOrderEvent**
  - 订单状态变更时触发
  - 接收成交、拒绝、撤销通知
  - 更新内部状态

**核心属性**：

- **Time**：当前时间（回测为模拟时间，实盘为系统时间）
- **Portfolio**：持仓状态（标的 → 持仓对象）
- **Securities**：订阅的标的（标的 → 证券对象）
- **Account**：账户信息（资金、保证金、权益）
- **Transactions**：订单簿（历史订单记录）

#### 1.2 数据订阅 API

**添加交易标的**：

- **AddEquity**：添加股票
  - 指定股票代码和数据频率
  - 回测时从数据库加载历史数据
  - 实盘时向 IBKR 订阅实时行情
  - 自动创建证券对象

- **未来扩展**：外汇、加密货币

#### 1.3 交易下单 API

**订单类型**：

- **MarketOrder**：市价单
  - 指定标的和数量（正数买入，负数卖出）
  - 回测时下一个时间点按开盘价成交
  - 实盘时立即发送给 IBKR
  - 返回订单凭证对象

- **LimitOrder**：限价单
  - 额外指定限价
  - 价格触达时成交
  - 实盘时在 IBKR 挂单

- **StopMarketOrder**：止损单
  - 指定触发价格
  - 价格触达后转为市价单

#### 1.4 持仓查询 API

**持仓对象属性**：

- 持仓数量
- 平均成本价
- 浮动盈亏
- 已实现盈亏
- 当前市值

**账户对象属性**：

- 可用资金
- 总权益
- 已用保证金
- 剩余保证金

#### 1.5 技术指标 API

**内置指标**：

- SMA：简单移动平均
- EMA：指数移动平均
- RSI：相对强弱指标
- MACD：异同移动平均线
- BB：布林带

**指标特性**：

- 自动预热（回测时使用历史数据填充）
- 自动更新（每次数据到达后更新）
- 提供就绪状态判断
- 提供当前值获取接口

#### 1.6 定时任务 API

**调度规则**：

- 按日期规则调度（每日、每周、特定日期）
- 按时间规则调度（开盘前、收盘前、特定时间）
- 支持组合规则（每周五收盘前）

**典型应用**：

- 每日开盘前执行预处理
- 每周五收盘前执行再平衡
- 每日收盘后执行清理任务

### 2. Engine Layer（引擎层）

#### 2.1 Backtesting Engine（回测引擎）

**核心职责**：模拟历史环境下的策略执行

**主循环流程**：

1. 加载策略，调用初始化方法
2. 获取订阅标的的历史数据
3. 按时间戳排序所有数据点
4. 遍历每个时间点：
   - 更新当前时间
   - 处理待成交订单
   - 更新持仓市值和账户权益
   - 推送数据给策略触发回调
   - 处理策略生成的新订单
   - 记录权益曲线和交易日志
5. 计算绩效指标
6. 生成回测报告

**时间管理器**：

- 管理回测时间轴
- 跳过非交易日
- 支持多时间周期数据对齐
- 提供市场开放状态查询

**订单成交模拟**：

- **即时成交模式**（默认）
  - 市价单：下一个 Bar 的开盘价成交
  - 限价单：价格触达时按限价成交
  - 止损单：触发后按下一个 Bar 开盘价成交

- **延迟成交模式**（可选）
  - 模拟订单延迟（若干 Bar 后成交）

**滑点模型**：

- 固定滑点：每笔固定金额
- 百分比滑点：价格的固定比例
- 成交量滑点：根据订单量与市场成交量比例

**手续费模型**：

- IBKR 美股费率：每股 0.005 美元
- 最低收费：1 美元
- 最高收费：订单金额的 0.5%

**结果收集器**：

- 记录每日权益值
- 记录每笔交易明细
- 记录持仓变化历史
- 记录订单执行情况

#### 2.2 Live Trading Engine（实盘引擎）

**核心职责**：接收实时数据，驱动策略，执行真实订单

**启动流程**：

1. 加载策略，调用初始化方法
2. 连接 IBKR
3. 从 IBKR 同步当前持仓和资金
4. 订阅策略需要的实时行情
5. 启动事件循环

**实时数据处理器**：

- 监听 IBKR WebSocket
- 接收实时 Tick 或 Bar 数据
- 数据标准化（统一格式）
- 缓存最新价格到 Redis
- 触发策略数据回调

**订单路由器**：

- 接收策略生成的订单对象
- 执行风控检查
- 转换为 IBKR 订单格式
- 发送给 IBKR
- 处理订单拒绝情况

**状态同步器**：

- **定时同步**（每分钟）
  - 查询 IBKR 持仓
  - 查询账户资金
  - 查询待成交订单
  - 更新本地状态

- **事件驱动同步**
  - 订单成交时立即更新持仓
  - 订单状态变更时立即更新订单簿

**风控管理器**：

- **资金检查**
  - 下单前检查可用资金
  - 防止超额下单

- **持仓限制**
  - 单只股票最大持仓比例
  - 总持仓数量上限

- **交易频率限制**
  - 单日最大交易次数
  - 防止频繁交易

**断线重连机制**：

- 检测 IBKR 连接状态
- 断线后自动重连
- 重连后重新订阅行情
- 重新同步持仓和订单状态

### 3. Data Layer（数据层）

#### 3.1 历史数据管理

**数据下载器**：

- **IBKR 历史数据 API**
  - 支持日线和分钟线
  - 自动处理请求频率限制（每 10 秒最多 60 次）
  - 断点续传（检查已有数据，只下载缺失部分）

- **yfinance 备用源**
  - IBKR 失败时使用
  - 仅支持日线数据

**下载策略**：

- 批量下载模式
- 检查数据库已有数据
- 计算缺失时间段
- 从数据源下载缺失数据
- 数据质量检查
- 写入数据库
- 等待防止触发限流

**数据存储（PostgreSQL）**：

**历史 Bar 数据表**：

- 字段：标的、时间戳、频率、开高低收、成交量
- 主键：标的 + 时间戳 + 频率
- 索引：标的 + 时间戳

**股票元数据表**：

- 字段：标的、名称、交易所、行业、市值、更新时间
- 主键：标的

**数据访问接口**：

- 按时间范围查询 Bar 数据
- 查询最新 Bar
- 检查数据是否存在

#### 3.2 实时数据管理

**实时订阅器**：

- 使用 ib_insync 订阅实时行情
- 支持 Tick 级别和 Bar 级别
- 自动处理断线重连后的重新订阅

**订阅模式**：

- Bar 模式：1 分钟、5 分钟等
- Tick 模式：每笔成交

**数据缓存（Redis）**：

- **最新价格缓存**
  - 键格式：price:标的
  - 存储价格、时间戳、成交量
  - 5 分钟过期

- **实时 Bar 缓存**
  - 键格式：bars:标的:频率
  - 存储最近 100 根 Bar
  - 使用列表数据结构

**数据归一化**：

- 统一时间戳格式（UTC）
- 统一字段命名（OHLCV）
- 处理股票分拆和分红调整
- 处理缺失值

#### 3.3 数据质量检查

**检查项**：

1. 缺失值检查
2. 异常值检查（价格为零或负数）
3. 时间序列完整性
4. OHLC 逻辑检查（Low ≤ Close ≤ High）
5. 成交量异常检查
6. 价格跳变检查

**输出**：

- 检查报告
- 问题数据列表
- 是否通过判断

### 4. Brokerage Layer（券商层）

#### 4.1 IBKR 适配器

**连接管理器**：

- 连接 TWS 或 IB Gateway
- 验证连接状态
- 注册事件回调
- 断开连接和清理

**订单执行接口**：

- **下单方法**
  - 支持市价单、限价单、止损单
  - 创建标准合约对象
  - 创建订单对象
  - 提交给 IBKR
  - 返回订单凭证

- **撤单方法**
  - 根据订单 ID 取消订单

- **改单方法**
  - 修改订单价格或数量

**持仓查询接口**：

- 查询所有持仓
- 查询单只股票持仓
- 返回持仓数量、成本、市值、盈亏

**账户查询接口**：

- 查询账户摘要
- 返回现金、权益、购买力、保证金

**订单状态回调**：

- IBKR 订单状态变更时触发
- 状态类型：待提交、已提交、已成交、部分成交、已撤销等
- 更新本地订单状态
- 触发策略订单事件回调
- 记录到数据库

#### 4.2 订单管理

**本地订单簿**：

- 添加新订单
- 更新订单状态
- 查询未成交订单
- 查询指定订单

**订单持久化（PostgreSQL）**：

**订单表字段**：

- 订单 ID、标的、方向（买/卖）
- 数量、订单类型
- 限价、止损价
- 状态、成交数量、成交均价
- 手续费
- 创建时间、更新时间、成交时间

#### 4.3 持仓管理

**持仓跟踪器**：

- 更新持仓（成交后调用）
- 查询持仓
- 查询所有持仓
- 计算组合总市值

**盈亏计算器**：

- **浮动盈亏计算**
  - 公式：（当前价 - 平均成本）× 持仓数量

- **已实现盈亏计算**
  - 公式：卖出价 - 平均成本
  - 使用先进先出或平均成本法

### 5. Infrastructure Layer（基础设施层）

#### 5.1 数据库管理

**PostgreSQL 配置**：

**数据库划分**：

- **market_data**：历史行情数据
- **trading**：订单和持仓记录
- **backtest**：回测结果

**优势**：

- 成熟稳定的关系型数据库
- 良好的并发性能
- 丰富的 SQL 功能
- 支持时间序列数据优化

**后期优化**：

- 可安装 TimescaleDB 插件提升时序数据性能
- 分区表优化大表查询
- 建立合适的索引

#### 5.2 缓存管理

**Redis 用途**：

1. **实时行情缓存**
   - 键：price:标的
   - 值：价格、时间戳
   - 过期时间：5 分钟

2. **策略状态缓存**
   - 键：strategy:名称:state
   - 值：持仓、指标状态
   - 过期时间：永久

3. **实时 Bar 缓存**
   - 键：bars:标的:频率
   - 类型：列表
   - 存储最近 100 根 Bar

4. **行情分发（Pub/Sub）**
   - 频道：market_data
   - 消息：行情数据

#### 5.3 任务调度

**APScheduler 定时任务**：

**盘前准备**（每日 9:00）：

- 检查 IBKR 连接
- 更新隔夜数据
- 加载策略配置
- 启动实盘引擎

**盘中监控**（交易时段每分钟）：

- 检查策略运行状态
- 监控订单执行
- 记录日志

**盘后清算**（每日 16:30）：

- 同步最终持仓
- 计算当日盈亏
- 生成交易报告
- 备份数据

**每周数据更新**（周日 12:00）：

- 下载新上市股票数据
- 更新股票元数据
- 数据质量检查

#### 5.4 日志与监控

**Loguru 日志配置**：

- 按天轮转日志文件
- 保留 30 天历史日志
- 结构化日志格式

**日志级别**：

- DEBUG：调试信息（数据接收、计算过程）
- INFO：正常操作（订单提交、成交、持仓变化）
- WARNING：警告（数据缺失、连接重试）
- ERROR：错误（订单拒绝、连接失败）
- CRITICAL：严重错误（策略崩溃、资金异常）

**关键事件告警**：

**触发条件**：

1. IBKR 连接断开超过 5 分钟
2. 订单被拒绝
3. 单日亏损超过阈值（如 -5%）
4. 持仓偏离预期
5. 策略运行异常

**告警方式**：

- 邮件通知
- 微信企业机器人
- CRITICAL 级别日志
