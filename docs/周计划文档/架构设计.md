# QuantConnect 风格量化交易平台架构设计

## 核心设计理念

参考 QuantConnect 的架构，采用 **分层解耦 + 引擎驱动 + 事件驱动** 的设计模式，支持回测和实盘统一接口。

## 整体架构分层

| 层级 | 职责 | 核心组件 |
|------|------|----------|
| **Algorithm Layer** | 策略代码编写层 | QCAlgorithm 基类、策略 API |
| **Engine Layer** | 执行引擎层 | Backtesting Engine、Live Trading Engine |
| **Data Layer** | 数据馈送层 | Data Feed、历史数据、实时数据 |
| **Brokerage Layer** | 券商对接层 | Order Router、Position Manager、IBKR/其他券商适配器 |
| **Infrastructure Layer** | 基础设施层 | 消息队列、数据库、调度器、监控 |

---

## 各层详细设计

### 1. Algorithm Layer（策略层）

**职责**：提供统一的策略编写接口，屏蔽回测/实盘差异

**核心组件**：
- **QCAlgorithm 基类**：策略继承的基类，提供标准 API
  - `Initialize()`：初始化策略参数、订阅数据
  - `OnData(data)`：数据到达事件回调
  - `OnOrderEvent(event)`：订单状态变更回调
  - `SetBroker()`, `SetBenchmark()`, `Schedule()`
  
- **API 接口**：
  - 数据订阅：`AddEquity()`, `AddForex()`, `AddCrypto()`
  - 下单接口：`MarketOrder()`, `LimitOrder()`, `StopOrder()`
  - 持仓查询：`Portfolio`, `Securities`, `Account`
  - 指标计算：内置技术指标库（SMA、RSI、MACD 等）

**特点**：
- 策略代码无需关心数据来源（历史/实时）
- 无需关心订单路由细节
- 回测和实盘代码完全一致

---

### 2. Engine Layer（引擎层）

#### 2.1 Backtesting Engine（回测引擎）

**核心流程**：
1. **时间循环**：按时间戳遍历历史数据
2. **数据分发**：将 Bar/Tick 数据推送给策略
3. **订单模拟**：模拟订单成交逻辑（滑点、手续费）
4. **绩效计算**：实时计算收益、回撤、夏普比率

**关键模块**：
- **Time Manager**：时间轴管理，支持多时间周期
- **Fill Model**：成交模拟（即时成交、延迟成交、部分成交）
- **Slippage Model**：滑点模型
- **Fee Model**：手续费模型
- **Result Handler**：结果收集器（权益曲线、交易记录）

#### 2.2 Live Trading Engine（实盘引擎）

**核心流程**：
1. **实时数据订阅**：从券商或数据源接收实时行情
2. **事件驱动**：收到数据后触发策略 `OnData()`
3. **订单路由**：将策略订单发送给券商
4. **状态同步**：实时同步持仓、资金、订单状态

**关键模块**：
- **Real-time Data Handler**：实时数据处理
- **Order Router**：订单路由与重试机制
- **State Synchronizer**：状态同步器（定期同步账户状态）
- **Risk Manager**：风控模块（资金上限、持仓限制）

---

### 3. Data Layer（数据层）

#### 3.1 Data Feed（数据馈送）

**职责**：统一数据接口，支持多数据源切换

**核心组件**：
- **Historical Data Provider**：历史数据提供者
  - 本地数据库（PostgreSQL/TimescaleDB）
  - 外部 API（yfinance、Tushare、AKShare）
- **Real-time Data Provider**：实时数据提供者
  - WebSocket 订阅（IBKR、Binance）
  - 消息队列（Redis Pub/Sub）
- **Data Normalization**：数据标准化模块
  - 统一时间戳格式（UTC）
  - 统一字段命名（OHLCV）
  - 支持多频率（Tick、1min、1hour、1day）

#### 3.2 Data Storage（数据存储）

| 数据类型 | 存储方式 | 用途 |
|---------|---------|------|
| 历史 OHLCV | TimescaleDB/PostgreSQL | 回测数据源 |
| Tick 数据 | ClickHouse/Parquet | 高频回测 |
| 实时行情 | Redis | 缓存最新价格 |
| 策略结果 | PostgreSQL | 绩效分析 |

---

### 4. Brokerage Layer（券商层）

**职责**：对接券商 API，处理订单执行和持仓管理

**核心组件**：

#### 4.1 Brokerage Interface（券商接口）

定义标准接口，各券商实现适配器：
- `PlaceOrder(order)` → 下单
- `CancelOrder(orderId)` → 撤单
- `GetOpenOrders()` → 查询挂单
- `GetPositions()` → 查询持仓
- `GetAccountBalance()` → 查询资金

#### 4.2 Order Manager（订单管理）

- **Order Book**：本地订单簿，记录所有订单状态
- **Order State Machine**：订单状态机（Submitted → PartiallyFilled → Filled / Cancelled）
- **Order Reconciliation**：订单对账（定期与券商核对）

#### 4.3 Position Manager（持仓管理）

- **Portfolio Tracker**：持仓跟踪器
- **PnL Calculator**：盈亏计算
- **Margin Monitor**：保证金监控

---

### 5. Infrastructure Layer（基础设施层）

#### 5.1 消息队列

- **Redis Pub/Sub**：实时行情分发
- **RabbitMQ/Kafka**（可选）：高吞吐量场景

#### 5.2 数据库

- **PostgreSQL**：存储策略配置、历史订单、绩效数据
- **TimescaleDB**：时序数据（OHLCV）
- **Redis**：缓存最新价格、策略状态

#### 5.3 调度器

- **APScheduler**：定时任务（数据更新、策略执行）
- **Cron Jobs**：盘前准备、盘后清算

#### 5.4 监控与日志

- **Loguru**：结构化日志
- **Prometheus + Grafana**（可选）：系统监控
- **Alert System**：异常告警（订单失败、断线重连）

## 核心工作流

### 回测模式

1. 用户编写策略继承 `QCAlgorithm`
2. 设置回测参数（起止时间、初始资金、数据频率）
3. 引擎加载历史数据 → 按时间戳循环
4. 每个时间点触发 `OnData()` → 策略生成订单 → 模拟成交
5. 计算绩效指标 → 生成报告

### 实盘模式

1. 用户部署策略到实盘引擎
2. 引擎启动 → 连接券商 → 订阅实时行情
3. 收到行情 → 触发 `OnData()` → 策略生成订单 → 发送给券商
4. 券商返回订单状态 → 触发 `OnOrderEvent()` → 更新持仓
5. 定期同步账户状态、记录交易日志

## 关键设计决策

### 统一时间抽象

- 回测：时间由引擎控制，可快速回放
- 实盘：时间是真实系统时间
- 策略通过 `self.Time` 获取当前时间，无感知差异

### 事件驱动架构

所有模块通过事件通信：
- `DataEvent`：新数据到达
- `OrderEvent`：订单状态变更
- `FillEvent`：成交事件
- `PositionEvent`：持仓变更

### 插件化设计

- **Data Source Plugin**：支持扩展新数据源
- **Brokerage Plugin**：支持扩展新券商
- **Indicator Plugin**：支持自定义技术指标
- **Risk Plugin**：支持自定义风控规则
